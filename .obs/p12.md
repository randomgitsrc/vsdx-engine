# P1-2 复核：三个子问题中两个成立

**2026-11-18 实测**

## 成立

### 1. 删除带连线的节点必然失败

```
$ update --delete-missing （删除 web 节点）
  ok: false
  error: unhandled
  message: Connector 'e1' references a source shape that is not part of the page
```

删节点时未级联删除相关连线，导致悬空引用，写盘校验失败。

### 2. 删除报告误报

删除孤立节点 `lone` 后：

```
changes: [('node.deleted','lone'), ('node.deleted','5')]
```

`'5'` 是**文本块 title 的 visioShapeId**，而该文本块在产物中**仍然存在**。
即报告了一条不存在的删除。

## 不成立

### 3. 文本块 ID 不稳定 —— **成立**（我最初测错了场景）

第一次测（无删除操作）ID 确实保持 `5 → 5`，我据此判定该条不成立。

但**在有删除操作的场景下**暴露了真相：

```
保真守卫报告: 形状 '4' 的几何行数 2 → 0
模型里的文本块: VisioShapeId = 5
```

**同一个文本块，在 modify 前后 ID 从 4 变成 5。** `VisioTextBlockBridge` 每次写回都
移除旧形状、重建新形状，因此 ID 会变——按 `visioShapeId` 的引用会失效。

这同时导致保真守卫误判：它看到形状 `4` 几何减少（实际是该形状已被删除并重建为 `5`），
判定为"几何损坏"并拒绝输出。

**教训**：单次往返测不出这个问题，必须有删除或重建操作的场景。
