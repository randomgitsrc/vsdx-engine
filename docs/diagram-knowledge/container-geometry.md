# 容器几何：四个常量与推导公式

**状态：** Verified（源码 + 实测）
**日期：** 2026-11-19
**用途：** 手工摆放容器内节点时，避免撞标题或留白失衡

---

## 一、为什么需要这份文档

独立 Agent 在制图时出现了 **10 处 `container.heading-collision`**——节点放进容器就撞标题。
`SKILL.md` 当时只说「通常用 `autoSize: true` 解决」，但那不解决「容器高度固定时节点撞标题」。

Agent 花了约 35 分钟读 `DiagramLayout.cs` 等 8 个源文件，才反推出下面的常量。**这些数字应该在这里。**

---

## 二、四个常量

`src/Vsdx.Engine/DiagramLayout.cs`：

| 常量 | 值（英寸）| 作用 |
| --- | --- | --- |
| `ContainerHeading` | **0.46** | 标题带高度 |
| `HeadingClearance` | **0.12** | 标题与首个成员之间的间隙 |
| `ContainerPaddingBottom` | **0.22** | 容器底边到成员底边的距离 |
| `ContainerPaddingX` | **0.30** | 容器左右边到成员的横向距离 |

前三个可用 `group.style.headingHeight` / `paddingBottom` 覆盖；`ContainerPaddingX` 可用 `group.style.paddingX` 覆盖。

---

## 三、推导公式

容器由**成员**反推，公式是精确的：

```
容器高 = 最高成员高 + 0.46 + 0.12 + 0.22
       = 最高成员高 + 0.80
容器宽 = 最右成员右沿 - 最左成员左沿 + 0.30 × 2
```

**实测验证**（成员高 0.6）：容器高 `1.400` = `0.6 + 0.80` ✓
**实测验证**（成员高 1.4）：容器高 `2.200` = `1.4 + 0.80` ✓

## 四、手工摆放时的关键约束

### 4.1 成员**不是**在容器内居中

仓器顶部到最高成员的顶部 = **0.58 英寸**（`0.46 + 0.12`），底部到成员底部 = **0.22 英寸**。

```
┌─────────────────┐  ← 容器顶
│  标题带  0.46   │
│  ─间隙─  0.12   │  ← 最高成员的顶边在这里
│                 │
│     成员        │
│                 │
│  ─padding 0.22  │  ← 成员底边
└─────────────────┘  ← 容器底
```

**如果按「垂直居中」摆放，成员顶部会比应有位置高 0.18 英寸，直接撞进标题区。**

### 4.2 同一容器内成员高度不同时，**彼此中心对齐**

实测：容器内一个 0.6" 节点和一个 1.4" 节点，容器 `y[4.080, 6.280]`——

| 节点 | 底 | 顶 | 中心 |
| --- | --- | --- | --- |
| 高的（1.4"）| 4.300 | 5.700 | **5.000** |
| 矮的（0.6"）| 4.700 | 5.300 | **5.000** |

**两个成员的中心相同**（都是 5.000）。而容器中心是 `(4.080+6.280)/2 = 5.180`——
所以**成员整体比容器中心低 0.18 英寸**，那个差距就是标题与间隙多出来的那部分。

只有**最高的那个**成员的顶部会落在「容器顶 - 0.58」；矮的成员上下都不贴边。

### 4.3 因此手工摆放的最小公式

若要显式指定容器高度 `H` 并放入高 `h` 的节点：

```
节点中心 Y = 容器底 + 0.22 + h/2
容器高 H   ≥ h + 0.80
```

**`H` 小于 `h + 0.80` 时，容器会被撑大**——`DiagramLayout.Apply` 会覆盖你给的值。

## 五、如何验证自己的摆放

```bash
vsdx-tool check-layout --input out.vsdx --json | grep heading-collision
```

`container.heading-collision` 出现，就说明有成员顶进了标题带。
`check-layout` 只报告「进入标题区」，**不告诉你标题区多高**——那正是本文档存在的理由。
