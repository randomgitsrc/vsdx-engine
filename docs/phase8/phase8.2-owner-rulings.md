## D3 — `BaseSize`

**负责人原文：**

> 接受缩放基准方案，但修正语义定义。
> 当前源码注释明确说明 BaseSize 是 Base node-title size in points。
> 因此 BaseSize 应代表 NodeTitle 的目标绝对字号，不是所有节点统一字号。
> scale = BaseSize / TypeScale.NodeTitle
> 将比例应用于所有文本角色，保留 DiagramTitle、RegionTitle、NodeTitle、
> NodeCaption、EdgeLabel、Annotation 的层级关系。
> 显式对象字号仍然优先。MinReadableSize 夹紧时必须报告。
> 字体确定必须发生在文字测量和布局之前，确保几何尺寸与最终字号一致。

**裁决：** 缩放基准，`scale = BaseSize / TypeScale.NodeTitle`。

## D-4 — TextBlock 字体回读

**状态：** ✅ **已由任务书 §3.5 与 §4.4 裁定为方案 A**

我上一轮把它作为"待裁决"上报，但它其实被任务书两条要求夹定了：

**任务书 §3.5（第 281 行）明确要求：**

> - 样式最终写入真实 VSDX；
> - **Reader 能正确读回已支持的样式；**
> - 保存后的 VSDX 再次渲染，样式没有丢失；
> - **无法表达或渲染的样式必须报告。**

**任务书 §4.4 的限制范围：**

> 4. 不为了视觉系统**重写**现有 VSDX Writer / Reader。

**两条合起来：**

| 约束 | 含义 |
| --- | --- |
| §3.5「Reader 能正确读回」 | TextBlock 字体要么能读回，要么必须**报告**为无法表达 |
| §4.4 禁止「重写」 | 但修一处字体注册**不是重写**，是补一个缺失的注册 |

**因此方案 B（声明"不回读"）需要额外满足 §3.5 的"必须报告"**——
即每次遇到 TextBlock 自定义字体都要进 `unmetConstraints`。
那比修好它更啰嗦，且调用方每次都要处理同一个已知退化。

**裁决：方案 A —— 修 `VisioTextBlockBridge`，让字体注册进 `FaceNames`。**

**修法（两条路径，选其一）：**

| 路径 | 做法 | 影响 |
| --- | --- | --- |
| A1 | TextBlock 改用库的 `VisioTextStyle.FontFamily`，在**保存前**创建 | 改动较大，但走与 Node 相同的已验证路径 |
| A2 | 保存后补 `<FaceName>` 并让 `Font` cell 用索引引用 | 改动局部，但需正确维护 `document.xml` 的索引 |

**推荐 A1**：与 Node 共用同一条路径，避免两套字体机制长期并存——
这正是本审计反复出现的缺陷模式（同一个能力两条路径、行为不一致）。

**T2 工时：中。** 不是因为复杂，而是因为要真正验证"写入 → 注册 → 读回"整条链，
而不是再一次"写进去就算完成"。
