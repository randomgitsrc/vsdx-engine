# Phase 8.0 风险、依赖与阶段拆分

---

## 1. 风险登记

按"影响 × 可能性"排序。每条包含触发信号与缓解措施。

### R1【高】外部 VSDX 几何注入可能无法在 OfficeIMO 之上修复

| 项 | 内容 |
| --- | --- |
| 影响 | P0 保真缺陷无法修复，外部非矩形形状会被破坏 |
| 可能性 | 中 |
| 证据 | 实测：外部无几何 shape 经 update 后每个都被注入矩形 Geometry |
| 触发信号 | 定位后发现合成发生在 `OfficeIMO` 的 `Save` 内部且无开关可关 |
| 缓解 1 | 保存后 patch：记录原文件中无 Geometry 的 shape ID，删除新增段 |
| 缓解 2 | 若 patch 不可行 → 降低到"仅新建文件可靠"，外部编辑标记为受限能力 |
| 缓解 3 | 换路：对"仅改文字/样式"的场景绕开重写，直接改原始 XML |

**这条风险决定 Phase 8.1 的第一步是"定位根因"而非"开始写代码"。**

### R2【高→低】图片能力（已实验推翻风险）

| 项 | 内容 |
| --- | --- |
| 影响 | 任务 §4.1 列的"图片"无法交付 |
| 可能性 | ~~中高~~ → **低（已实验推翻）** |
| 证据 | 反射确认 OfficeIMO 3.6.1 无 image/picture API，但**包格式支持** |
| **实验结果** | **实验 2 已通过**：手写 `media/image1.png` + `ForeignData` + 关系后，包校验 VALID、渲染成功 28693 bytes；`[Content_Types].xml` 库已写 `png/jpg/emf`，无需手工补 |
| 残余风险 | ⚠️ **渲染器只画占位框，不显示真实位图**——图片能存进 VSDX，但预览不反映内容 |
| 缓解 1 | 已不必要（实验通过） |
| 缓解 2 | 需在能力声明中明确"预览为占位，Visio 中才显示真实图片" |

### R3【中】XML patch 累积导致维护失控

| 项 | 内容 |
| --- | --- |
| 影响 | 每次 OfficeIMO 升级都要复核多处 patch，易静默失效 |
| 可能性 | 中（当前 2 处，若图片/路径/SVG 都要 patch 则到 5+） |
| 触发信号 | patch 数 ≥ 5，或某次升级导致现有 patch 失效 |
| 缓解 1 | 每个 patch 必须有"失败可见"警告（现有 `VisioNestingBridge` 已有） |
| 缓解 2 | patch 数达 5 时，评估直接操作 OPC 的可行性 |
| 缓解 3 | 给 patch 加集成测试：外部文件 → patch → 回读 → 断言 |

### R4【中】嵌套容器 join key 依赖容器标题文本

| 项 | 内容 |
| --- | --- |
| 影响 | OfficeIMO 若改变容器文本写入方式，嵌套关系静默丢失 |
| 可能性 | 中低 |
| 证据 | 包内容器 shape 的 `<Text>` 等于组名，是当前唯一可靠 join key |
| 触发信号 | `write.nested-group-unresolved` 警告出现 |
| 缓解 | 已在无匹配时记警告；Phase 8.1 应改为按"写入顺序 + 索引"而非文本匹配 |

### R5【中】"区域协调"可能演化成强制统一构图

| 项 | 内容 |
| --- | --- |
| 影响 | 违背任务 §9 的设计原则 |
| 可能性 | 中 |
| 触发信号 | 出现"Engine 决定区域该多大"的逻辑 |
| 缓解 | ADR-005 明确：区域尺寸由 `DesignSpec` 给，Engine 只在框内排布 |

### R6【中】共享干线布线重演 Phase 7 失败

| 项 | 内容 |
| --- | --- |
| 影响 | 做出一个会穿过节点的路由器 |
| 可能性 | 中高（已经失败过一次） |
| 证据 | Phase 7 实验：绕行 1.40→1.89，新增 9 处 `edge.through-node` |
| 触发信号 | 未先做通道预留就实现共享干线 |
| 缓解 | **顺序强制**：先有通道预留（布局时留条带），再谈共享干线 |
| 缓解 | 任何布线改动必须过 `edge.through-node` 零容忍断言 |

### R7【低】新增对象影响既有 54 项已验证能力

| 项 | 内容 |
| --- | --- |
| 影响 | 回归 |
| 可能性 | 中 |
| 缓解 | 每阶段必须跑全量 283 项 + 18 个基准硬约束 |
| 基线 | `docs/phase7/baseline-report.md` 已记录可对照数字 |

### R8【低】文档数字漂移

| 项 | 内容 |
| --- | --- |
| 影响 | 不同文档的完成状态互相矛盾（任务 §3.2 第 9 点） |
| 缓解 | 本阶段所有数字均由脚本统计（见 `capability-matrix.md` 复核命令） |

## 4. 阶段拆分与验收标准

### Phase 8.1 — P0 保真 + 通用对象 + 纵向切片

> **实施顺序按负责人指定（A→G），不得调换。**
> 尤其在 P0 保真未解决前，不扩展大量图形对象。

**A. 先修复 P0 Geometry 注入，并建立外部 VSDX 保真回归样本**
1. 定位根因：是 OfficeIMO `Save` 合成，还是本项目写入器触发
2. 尝试 OfficeIMO 上层修复；不行则 OPC 局部修改
3. **若两者都无法保证保真 → 对受影响操作安全拒绝**，返回能力限制，
   **不得静默生成可能损坏原图形的 VSDX**（负责人意见 1）
4. 建立外部 VSDX 保真回归样本集（含无 Geometry / 自定义 Geometry / 多 shape）

**A2. 最小保真结构对比测试（负责人意见 7，提前到 8.1）**
不必等 8.5 的完整 `check-fidelity`，8.1 先落地最小版：
比对修改前后的 `<Shape>` 集合、每 shape 的 `Section N=` 集合、`<Connect>` 数量。
作为 P0 修复的**验收证据**，也是后续所有阶段的守门测试。

**B. 修复 ShapeOrder 的读取和写入**（见 ADR-002b）
1. Reader 保留 XML 真实 `<Shape>` 顺序
2. Writer 按 `Page.ShapeOrder` 输出
3. 验收：5 个重叠 shape 的顺序经往返后不变

**C. FreePath 读取、创建、编辑、安全保留**（负责人意见 2）
1. 新增 `FreePath` 类型（几何段 + 样式）
2. Reader 识别 `Section N="Geometry"`，不再误标 Rectangle
3. **暂不支持的 Geometry 指令必须原样保留**，不做有损转换
4. 创建 / 读取 / 编辑 / 保存 / 重新读取 全链路验证

**D. TextBlock**
标题 / 副标题 / 注释 / 图例；不参与节点布局，字号走 `TypeScale`

**E. Diagram IR 多页协议**

**F. 真实 VSDX 纵向切片 + L1–L3 验收**

**G. 安排 L4 Visio 原生验证**：自由路径、文本、Z-order、外部文件编辑

**纵向切片必须包含：** Node/Edge + 独立文本 + 自由路径 + 语义符号 + 区域背景 + 各自样式

**验收标准**

| # | 标准 | 复核方式 |
| --- | --- | --- |
| 1 | 原有 283 项测试全过 | `dotnet test` |
| 2 | 18 个基准硬约束全过 | `check-layout` |
| 3 | **外部文件加节点后，原 shape 的 Geometry 段数不变** | 解包 XML 计数 + 保真对比测试 |
| 3b | 无法保证保真时**安全拒绝**并返回能力限制 | 断言不会静默生成 |
| 3c | `ShapeOrder` 往返后 `<Shape>` 顺序不变 | 保真对比测试 |
| 4 | 新对象真实进入 VSDX 并可回读 | 解包 + `export-model` |
| 5 | 对象 ID 与关系稳定 | 三代往返 |
| 6 | Renderer 反映保存后内容 | 打开 PNG |
| 7 | 不支持的对象显式报错或降级 | `ExecutionResult` |

**退出条件：** 标准 3 未达成则不得进入 8.2（保真是底线）。

### Phase 8.2 — 视觉样式与主题执行

**任务**
1. 实现 `theme.palette`（4 套命名调色板），未知 palette 报 `unmetConstraints`
2. 建立三级样式解析器 `ResolveStyle(node, ir, spec)`
3. 容器标题 / 连线标签纳入 `TypeScale`
4. 统一 Renderer 与 VSDX 的样式映射

**验收标准**

| # | 标准 |
| --- | --- |
| 1 | 同一结构 + 3 份不同 DesignSpec → 输出明显不同 |
| 2 | 未知 palette 出现在 `unmetConstraints` |
| 3 | 字号层级在渲染图中可辨（标题 > 区域 > 正文 > 标签） |
| 4 | 保存/重读/渲染后样式不变 |
| 5 | 不内置固定风格包（只用参数面组合） |

**退出条件：** 标准 2 未达成则违反项目自己的协议契约。

### Phase 8.3 — 原生图形与资产

**任务**（实验已在 8.0 完成，直接进入实现）
1. 媒体写入器 + 模型字段 + 读取器
2. **Renderer 显示真实图片**（不接受占位框作为验收）
3. 接入 `VisioStencilCatalog` / `ImportMasters`
4. `AssetResolver` + 降级路径
5. 资产元数据（语义 id / 默认尺寸 / 连接点 / 许可证 / 归属 / 可编辑等级）

**验收标准**

| # | 标准 |
| --- | --- |
| 1 | 至少 1 个原生 master 资产可用（创建/保存/回读/渲染/增量改） |
| 2 | 至少 1 个 Stencil 形状可用（同上） |
| 3 | 资产缺失时降级到矩形**并报告**，不静默 |
| 4 | 许可证/归属写入可回读 |
| 5 | 图片真实嵌入、读回、替换，且 **Renderer 显示真实位图** |

**退出条件：** 标准 5 若只能做到占位框，**不得判定 8.3 通过**，
须向负责人报告并决定是否引入图像解码依赖。

**验收标准**

| # | 标准 |

## 5. 贯穿性要求

| 要求 | 落实方式 |
| --- | --- |
| 不以类/接口数量衡量进展 | 每阶段验收只看可交付产物与保真报告 |
| 不以机器检测代替视觉验收 | 每阶段至少一张真实 PNG 附人工评述 |
| 不静默忽略约束 | `unmetConstraints` 必须覆盖所有声明 |
| 不以测试通过率代替能力 | 基准 + 真实产物 + 保真比对三者并用 |
