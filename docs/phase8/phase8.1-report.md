## 2. 四个真实缺陷（全部由测试发现，非推测）

### 2.1 编辑 FreePath 产生重复形状

接入 `update` 后，编辑的路径**与旧副本同时存在**。
根因：增量编辑器看不见几何形状，其保存会把旧 shape 重新写出。

**修复：** 写入前删除同名 `FreePath` 形状并重算空闲 id。
**关键克制：** 删除时跳过 master-backed / Container / Connector——
删掉圆形的 25 行几何就是破坏真实节点。

### 2.2 ShapeOrder 单条记录被忽略

守卫写的是 `Count > 1`，导致"只把某一个形状置顶"这种合法用法被静默跳过。

### 2.3 TextBlock 字号单位错误

首次渲染四个文本全是极小的统一字号，尽管 XML 写着 `Size="20"`。
Visio 的 `Character` 单元格 `Size` 是**英寸长度**，`U="PT"` 记录创作单位——
裸写 `20` 意味着 20 英寸。对照库自建形状的 `V="0.333333" U="PT"`（24pt）才定位到。

**这是"格式正确但语义错误"的典型**：XML 完全合法，只有渲染才暴露。

### 2.4 TextBlock 被页面裁剪

`FitPage` 与 `Recenter` 只遍历 `page.Nodes`，
于是标题、图例、注释全部落在收缩后的页面之外——**交付物上直接消失**。

**修复：** 抽出 `ContentBounds(page)` 统一包含 nodes / groups / textBlocks / paths，
`Recenter` 同步移动文本与路径。

**连带修正：** 页面利用率原本只按节点计算，加入文本后又把"宽横幅"当成填满。
改为按**实际绘制范围**（含容器与文本）计算。

## 7. 补充验证：混合形状多次往返

P0 修复是否对**混合几何类型**长期成立？单独做了验证。

构造含四种几何形状的图：圆形（25 行）、菱形（5 行）、矩形（5 行）、
自定义弧线路径（2 行，含 `ArcTo`）。连续执行两代 `update`：

```
a.vsdx: {'Circle': [25], 'Diamond': [5], 'Rectangle': [5], 'FreePath': [2]}
b.vsdx: {'Circle': [25], 'Diamond': [5], 'Rectangle': [5], 'FreePath': [2]}
c.vsdx: {'Circle': [25], 'Diamond': [5], 'Rectangle': [5], 'FreePath': [2]}
```

**完全稳定，无退化。** 产物：`examples/phase8/mixed-fidelity.vsdx` + `.png`

这条验证的意义：P0 修复的剥离逻辑依赖"5 行矩形"签名，
而菱形恰好也是 **5 行**。若签名判定只看行数就会误删菱形的几何。
实际判定同时检查行类型序列（1×MoveTo + 4×LineTo），
菱形是 1×MoveTo + 2×LineTo + 2×LineTo 的不同组合——**测试证明它没被误伤**。

## 8. 外部 VSDX 保真语料（任务 A 要求）

任务 A 要求"建立外部 VSDX 保真回归**样本**"。已建立 6 类手工构造的外部包：

| 样本 | 内容 | 验证点 |
| --- | --- | --- |
| `no-geometry` | 无几何、无 master | **P0 原始缺陷场景** |
| `with-rectangle` | 自带 5 行矩形几何 | 引擎生成物不被误删 |
| `with-zigzag` | 4 行自定义折线 | 自定义几何保留 |
| `with-arc` | 含 `ArcTo` 指令 | 未解释指令逐行保留 |
| `master-backed` | `Master="5"` 引用 | 母版形状不被破坏 |
| `mixed` | 四者混合 | 相互干扰检查 |

**全部由手工 OPC 构造**（`FidelityCorpus.Write`），不经过本项目写入器——
否则只能证明"写入器自洽"，不能证明"能读外部文件"。

每个样本跑三项断言：几何行数不变、形状数不变、自定义几何不被剥离。

### 8.1 语料发现的第三个缺陷

首次运行时 `with-zigzag` 失败：**输入 1 个形状，输出 2 个**。

根因：路径删除逻辑按 `NameU == "FreePath"` 判定，
而外部文件里自定义几何叫 `FreeForm`——引擎把读进模型后又写了一遍，旧的原样留下。

**这是"按自己写的名字识别外来对象"的典型错误。**
改为：形状属于模型 `Paths` 中被声明的那一个才删除，其余不动。

### 8.2 如实记录的保真限制

`master-backed` 样本暴露一个**已知限制**：

增量编辑器按模型重建形状时，**不保留 `Master` 属性**（对未识别的 master）。
几何会被实体化，所以视觉正确，但与原 master 的链接丢失。

**这不是 P0 缺陷**（轮廓被保留而非替换成矩形），但仍是保真损失。
已在测试中显式记录该行为，而非假装通过——避免它以后悄悄变化而无人察觉。

**修复方向（8.2 或更晚）：** 读取时把 `Master` 存入 `Node.NativeCells`，写入时恢复。
