## 2. 最重要的发现：依赖库被大量闲置

这是本次审计对技术路线影响最大的一条。

```
OfficeIMO.Visio 公开类型          : 256
VisioShape 成员                  : 162
VisioPage 成员                   : 299

本项目实际使用的类型              : 3
  VisioPage × 10 处
  VisioShape × 6 处
  VisioConnector × 1 处
```

**已实测可用但完全闲置的能力：**

```csharp
var doc = VisioDocument.Create("t.vsdx");
Console.WriteLine(doc.Masters.Count);                    // 0
var got = doc.ImportMastersAndGet("/path/to/base.vsdx");
Console.WriteLine($"{got.Count} masters");               // 5  ← 真实可用
// Circle / Hexagon / Rectangle / Parallelogram / Process
```

`VisioStencilShape` 已包含 `SourceLicense`、`SourceAttribution`、`PreviewImage`、
`SourceConnectionPoints`、`IsSupported` —— **正是任务 §8.3 要求的资产元数据**。

**这意味着什么：** 任务 §8.3 设想"建立资产系统"，而其中大半工作库已经做完。
Phase 8.3 的重点应从"建立"改为"接入 + 实验图片"。

## 3. 发现的最严重缺陷（P0，此前从未被测出）

**外部 VSDX 编辑会给每个 shape 注入矩形几何。**

取一个外部文件（4 shape + 1 container，**无 Geometry 段**），模型只加 1 个节点：

```
original: {'shapes': 6, 'geom': 0}
edited  : {'shapes': 8, 'geom': 8}   ← 每个原有 shape 都多了 Geometry
```

注入内容是硬编码 0→2×0.8 的矩形路径。

**影响：** 对本身是矩形的形状视觉无损；**对圆/菱形/自定义路径/依赖 Master 的形状，
原始形状被矩形覆盖**。该外部样本恰好全是矩形，因此掩盖了问题。

**为什么这是 P0：** 任务 §3.3 明确要求"保存时不破坏未修改的原生特性"。
当前违反该原则且**静默发生，无任何警告**。

**为什么 283 项测试没抓到：**

```console
$ grep -rn "Geometry" tests/Vsdx.Tests/*.cs
（无结果）
```

测试体系对外部文件的**非典型构造**完全没有覆盖——现有外部样本全是无几何的矩形。

## 5. 对任务书的三点修正建议

任务 §16 允许"发现设计不合理时基于技术证据提出修正"。

### 5.1 Phase 8.3 工作量被高估约三分之二

任务描述为"建立真正可扩展的原生图形和资产机制"，字面像是自建。
实测 Stencil 目录、母版导入、资产元数据（含许可证/归属）**库已提供**。

**建议：** 8.3 改为"接入 + 补元数据 + 图片实验"。

### 5.2 §4.1 的 11 类能力应分级

"图片"依赖未验证的库外能力（反射确认库无 image API），
"图标符号"依赖外部资产包，二者不应与"独立文本"（纯 XML 写入即可）同级。

**建议：** 分为"Engine 内生"（文本/路径/区域/组合）与"依赖外部"（图片/SVG/图标包），
后者以实验结论决定是否纳入验收。

### 5.3 L4 验证建议提前到 8.1 之后

Phase 8 要新增图片/SVG/自定义路径——**这些恰恰是 L1–L3 最难保证、L4 最容易暴露问题的特性**。
若等 8.5 才验，返工成本很高。

## 7. 最小纵向验证方案（Phase 8.1 用）

任务 §6 要求纵向切片包含：Node/Edge + 独立文本 + 自由路径 + 语义符号 + 区域背景 + 各自样式。

**建议案例：一页"系统全景图"**

| 元素 | 用途 | 验证点 |
| --- | --- | --- |
| 3 个 Node + 2 条 Edge | 保留语义对象 | 回归不破 |
| 1 个 `TextBlock`（主标题） | 独立文本 | 不参与布局，字号走 TypeScale |
| 1 个 `TextBlock`（图例） | 多文本组合 | 能与区域对齐 |
| 1 个 `FreePath`（分隔线/装饰） | 自定义几何 | XML patch 可行，Visio 能保留 |
| 1 个 Group（区域背景） | 区域 | 固定尺寸模式下不自动 resize |
| 每类不同样式 | 样式系统 | 三级解析生效 |

**链路：** IR → Model → Layout → Writer → 保存 → 回读 → Render → `check-layout`

**为什么要这个案例：** 它同时覆盖"新旧对象共存"和"各自样式"，
若架构有问题（例如 Z-order 或坐标变换），在这个案例上会立刻暴露。
