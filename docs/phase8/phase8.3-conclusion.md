# 阶段结论（2026-11-18）

本文件回答一个问题：**项目定义的核心目标，现在达到了什么程度？**

## 一、项目定义

> 让 AI Agent 能够创建、理解、修改和持续维护专业的 Microsoft Visio 图形，
> 并以**原生、可编辑的 VSDX 文件**作为最终交付物。

拆成五项：创建、理解、修改、持续维护、**原生可编辑**。

## 二、逐项结论

| 目标要素 | 结论 | 依据 |
| --- | --- | --- |
| **创建** | ✅ 已建立 | 五种结构实测，四种可交付 |
| **理解**（读回） | ✅ 已建立 | 读写往返测试覆盖；角色、样式、标签位置均能还原 |
| **修改**（增量） | ✅ 已建立 | `update`、`LocalRelayout`、版本存储 |
| **持续维护** | ⚠️ 部分 | 见第四节 |
| **原生可编辑** | ⬜ **未验证** | L4 从未执行 |

## 三、已建立的

### 创建：五种结构，四种可交付

| 场景 | 结构 | 分数 | 判定 |
| --- | --- | --- | --- |
| 跨境电商架构 | 3 层容器 | 98 | ✅ 可交付 |
| 部署拓扑 | 3 层容器 + 扇出 | 94 | ✅ 可交付 |
| 用户数据流 | 无容器长链 | 100 | ✅ 可交付 |
| 下单支付时序 | 有环 + 双向对 | 88 | ⚠️ 结构对，非时序形态 |
| 订单状态机 | 有环（手工坐标） | 95 | ⚠️ 结构对，无状态语义 |

18 个基准图全部通过硬约束。

### 检测：23 类问题

`check-layout` 能发现 23 类几何与文字问题，其中 **7 项为 error 级**
（`node.overlap`、`node.out-of-page`、`group.overlap`、`group.member-escapes`、
`edge.through-node`、`text.overflow-horizontal`、`text.overflow-vertical`）。

清单与文档由测试保证一致（`DetectorDocumentationTests`）。

### 协议诚实性

这是本项目最强调的性质，已实测确认以下情况**会被报告而非静默处理**：

| 情况 | 报告 |
| --- | --- |
| 纸张放不下内容 | `canvas.exceeded`，附实际尺寸 |
| 为容纳内容收缩 | `canvas.shrunk` |
| manual 下忽略方向 | `direction.manual-ignored` |
| 局部重排撞到别的容器 | `container_layout`，附重叠节点数 |
| 字号触底被提升 | `typography.min_size` |
| 未知枚举值 | `layout.unknown` / `direction.unknown` |

### 产物形态

- `canvas.mode=paper` 吸附标准纸张，实测三场景落在 A3
- 配色四套，40 个角色色全部 ≥ AA-large，37 个 ≥ AA
- 字体、字号层级、背景色、角色样式均可往返

## 四、未建立的

### 1. L4：原生可编辑（**最高**）

**从未执行。** 环境事实（2026-11-18 实测）：

- Windows 侧 `Program Files` 下**无 Office/Visio**
- `/mnt/c` 只读，无 PowerShell
- 装有 WPS，但**不能替代 L4**

`tools/l4/verify-visio.ps1` 已写好并做过静态审查（修掉三处会给出错误结论的问题），
但**从未运行**。

**L1（包结构）、L2（读回）、L3（渲染）都不能替代 L4。**

因此「原生、可编辑的 VSDX」目前是**假设**，不是结论。

**解除条件：** 一台装 Microsoft Visio 的 Windows 机器，或可写挂载的 `/mnt/c` + PowerShell。

### 2. 持续维护

增量编辑可用，但**未验证长期维护**：同一个文件经过多次往返、
在 Visio 中编辑后再由 Agent 接手、并发修改的合并——这些场景没有测试。

### 3. 专业水准

**没有判据。** 分数衡量几何约束，不衡量"这张图是否专业"。没有人类设计师评价过产物。

已记录六次"高分但观感差"的案例。最典型的一次：状态机图曾报 100 分，
而标题直接压在两个节点上——补上 `text.overlaps-node` 后降到 88 分。

**同一场景在不同夹具下分数不同（88 / 95 / 96 都出现过）**，这本身说明
"一个场景一个分数"不足以描述能力。

### 4. 两种结构

- **时序图**：模型层不支持（连线端点由节点决定，无法表达"生命线上的第 N 条消息"）
- **状态机**：能画，但没有状态语义（初态/终态/复合状态）

已写入 `docs/capability-boundaries.md`。

## 五、缺陷清单状态

25 项审计缺陷：**24 项已修，1 项待准则**。

### 独立审查（2026-11-18）

按章程 §5.3 发起了一次**真正的独立审查**（subagent，非自我检查）。
审查对象 HEAD `f7eabb6`，报告 15 项问题，全部处理：

| 组 | 数量 | 代表问题 |
| --- | --- | --- |
| P0 | 2 | `update` 无操作往返把居中对齐改成左对齐，而 `diff` 报"完全相同" |
| P1 | 5 | 容器几何修改被完全忽略；`cm` + `shrinkToFit` 触发双重换算 |
| P2 | 8 | `specVersion: 9.9` 被接受；畸形输入报 `unhandled` 与引擎故障同码 |

**独立审查找到的问题，测试套件一个都没发现。** 最典型的是 P0-1：
`diff` 完全不比较 `TextBlock`，因此"用 diff 验保真"的所有流程都是不可信的。

审查同时报告了 9 个「查过但没问题」的方面（IR 校验、失败不破坏产物、
error 级检测确实生效、manual 保留坐标等），这部分同样有价值。

剩项：缺陷 24（对比度无校验）。40 个角色色的实测对比度已在
`docs/phase8/palette-contrast.md` 列出，其中 3 个低于 WCAG AA（`enterprise` 的
`database`/`queue`/`storage`，均为 4.36:1）。**是否调深是设计决策**，需阈值准则。

## 七、结论

**Agent 能创建、理解、修改结构正确、样式一致、可读回的 VSDX 文件。**
引擎在 23 类问题上诚实报告，做不到的要求会出现在 `unmetConstraints` 里。

**但「原生可编辑」这一条从未验证**，而它正是项目定义的核心。在这个问题上，
项目当前的状态是**「已实现，未证明」**。

在 L4 执行之前，任何"完成了"的断言都是不成立的。
