## 0. 一句话结论

**引擎现在是可信的执行引擎，但还不是完整的专业制图引擎。**

它接收结构化内容 + 设计意图后，能稳定产出结构正确、可编辑、可验证的 VSDX，
并对做不到的事情如实报告。**缺口集中在表达丰富度**（混合布局、泳道、视觉组件、布线质量），
而不在正确性。

## 2. 审计推翻的既有结论

任务 §0 允许审计推翻此前设计。实际推翻了**两处**：

### 2.1 "18/18 基准可交付"不成立

Phase 6 以此作为能力达标证据。审计发现其中 microservices/complex
**页面右侧空白 7.09 英寸**（占页宽 35%），机器评分仍有 90。

**根因：** `create` 流水线顺序错误——页面尺寸在布局**之前**按作者旧坐标确定，
随后布局搬走所有节点。见 `phase0-6-implementation-audit.md` §2.11。

**修正后的口径：** 可交付 = 硬约束全过 **且** 页面利用率 ≥ 40% **且** 视觉审查无"明显不专业"项。

### 2.2 "嵌套容器受支持"不成立

Phase 0–6 从未测试嵌套。审计实测三重丢失：父关系、包内层级、成员归属。

## 4. 新增能力

### 4.1 三层结构化协议

```
Diagram IR（说什么）──┐
                      ├──▶ ProtocolRunner ──▶ ExecutionResult（做成了什么）
DesignSpec（怎么表达）─┘                    └──▶ VSDX + PNG/SVG
```

| 文档 | 职责 | Schema |
| --- | --- | --- |
| Diagram IR | 节点/关系/容器，**无需坐标** | `schemas/phase7/diagram-ir.schema.json` |
| DesignSpec | 布局/画布/字体/主题/约束 | `schemas/phase7/design-spec.schema.json` |
| ExecutionResult | 状态/诊断/未满足约束/映射 | `schemas/phase7/execution-result.schema.json` |

**核心保证：** 声明的约束要么满足，要么出现在 `unmetConstraints` 里。
未知约束码必须报 `unknown_constraint`，不得静默跳过。

### 4.2 容器级布局与局部重排

`LocalRelayout` 只重排指定容器内的成员，并在返回前**验证容器外节点逐字节未变**
（`IsolationBroken` 标志）。这是任务 §6.9"保护无关对象"的直接实现。

### 4.3 容器分带配色

此前所有容器共用写入器默认填充，整图读起来是一块。现按序分配克制的地带色。

## 9. 对下一阶段的建议

**不要**继续加功能清单式模块。按 `capability-gap-analysis.md` §4 的顺序：

1. **G6 扇出布线**（收益最大、风险最高，需完整回归）
2. **G4 泳道**（复用容器机制，成本低）
3. **G7 视觉组件**（提升成品感）
4. 然后才是 Figure Agent 侧的接入

**一个前置条件：** L4 Visio 验证必须尽早安排。当前所有"可编辑"结论都建立在
文件结构和第三方渲染之上，这在工程上合理，但对"专业交付"来说仍是未闭合的风险。
