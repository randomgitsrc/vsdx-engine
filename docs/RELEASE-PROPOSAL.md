## 二、发布前必须解决的一项

**L4 从未验证。** 本机无 Visio，`/mnt/c` 只读，WPS 不可替代。

项目定义的核心是「原生、可编辑的 VSDX」，而这一条**只有 L1–L3 证据**。
发布 1.0.0 意味着对外声称该版本可用，**但核心承诺未经验证**。

三个选项：

| 选项 | 做法 | 后果 |
| --- | --- | --- |
| **A** | 先做 L4 再发 1.0.0 | 需要 Visio 环境，时间不定 |
| **B** | 发 0.9.0，明确标注「L4 未验证」 | 诚实，但对外称不上 1.0 |
| **C** | 直接发 1.0.0，文档标注限制 | 与既有 `limitations.md` 一致，但风险最高 |

**我的建议是 B。** 理由：`limitations.md` 已如实标注 L4 未执行，
但版本号 1.0.0 本身是一个更强的信号——它意味着"我们验证过"。
0.9.0 + 明确的限制声明，比 1.0.0 + 脚注更诚实。
