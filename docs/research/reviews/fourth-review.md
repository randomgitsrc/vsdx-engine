## 二、评审的核心判断

> 三张图不是「排版没对齐」（对齐其实做得不错），而是**约束缺失**。
> 所以它们整齐但不可靠——而「整齐」正是最容易骗过验收的地方。

这个判断与本项目已有的结论一致：`check-layout` 测几何合规，测不到构图与正确性。

## 四、对两条硬伤的复核

评审的结论基于**送审时的产物**（`deploy` hash `68e75001`、`slack` hash `e15ea3d9`）。
本会话已在其后修复 P2 与界面问题，**部分结论需要重新测量**。

### (a) 连线穿框、箭头落错边 —— **在当前产物中不成立**

复核 `deploy-topology` 当前渲染：`API 实例 1` 顶边**正中有向下箭头**，入线垂直。

原因：waypoints 确实写入了产物（几何行数 5 行 = `MoveTo + 3×LineTo`），
正交路径生效。

### (b) 标签擦断边框、字号不足 —— **成立**

- 标签白底确实擦断边框（E8 已记录：渲染器不读 `TxtPin`，引擎无法控制）
- 字号：节点名与边标签在 VSDX 里**同为 8pt、同为 `#111111`**，层级扁平

**这一条是真的，且是当前最刺眼的问题。**

## 五、值得保留的正面结论

评审据实肯定了三处，这些应当保留为规范：

| 对象 | 肯定 |
| --- | --- |
| `cbo` | 骨架扎实：节点尺寸统一、列距一致、图例色值逐像素一致 |
| `deploy` | 内容最真实：IP、端口、语义标签齐备；LB 总线式扇出是专业做法 |
| `slack` | **唯一用线型承载语义**：控制面虚线、排空单元的三重编码（虚线边框 + 0% + 权重 0）|

评审明确建议：**把 slack 的状态编码保留为规范。**
