# 实验 E12：文字层级在默认 spec 下从未建立

**日期：** 2026-11-20
**状态：** 完成（已修）
**依据：** 第四轮评审 P5「文字只有有/无两档，边标签与节点名同级」

---

## 一、评审的观察

> 节点名与边标签在 VSDX 里**同为 8pt、同为 `#111111`**

**属实。**

---

## 二、根因：排版整段只在显式指定时运行

`DesignSpecApplier` 里，`TypeScale` 的应用被包在：

```csharp
if (spec.Typography.BaseSize is not null ||
    spec.Typography.FontFamily is not null ||
    spec.Typography.MinReadableSize > TypeScale.MinReadablePt)
{
    ... 所有层级赋值 ...
}
```

**默认 spec 三项都不满足，整段跳过。** 于是：
- 节点 `style.fontSize` = `null`
- 边标签 `labelFontSize` = `null`
- 两者都落到 Writer 默认值，**同字号同颜色**

实测默认 spec 下 `cbo`：节点 `None`、边标签 `None`。

---

## 三、第二处不一致：层级来源混用

修第一处时发现第二个问题。即使显式指定 `baseSize=14`：

| 元素 | 实测 | 应为 |
| --- | --- | --- |
| 节点 | 11.97pt | 14.0 |
| 边标签 | 11.45pt | 11.45 |

两者只差 **0.52pt**，而设计是 `body - 2.0`。

原因：节点在之前的改动里改为从**页面密度**推导（`pageScale.NodeTitle`），
而容器和边标签仍用**裸 `defaults`**（`NodeTitle` 固定 11）。两个来源混用，层级算错。

---

## 四、修复

1. **排版始终运行**（去掉 `if` 条件）
2. 容器标题与边标签改用 `pageScale`，与节点同源

实测默认 spec 下 `cbo`：

| 元素 | 修复前 | 修复后 |
| --- | --- | --- |
| 标题 | 无 | **16.92pt** |
| 节点 | 无 | **9.40pt** |
| 边标签 | 无 | **8.00pt** |

**三级层次建立，边标签比节点小 1.4pt。**

---

## 五、影响

- 所有场景的文字渲染变化，产物需重新生成
- 先前为「页面无法收缩」「图例过大」做的调整仍然有效，因为那些走的是 `pageScale`
- 显式 `typography` 的行为不变，只是现在有默认基线

---

## 六、教训

**一个只在特定条件下运行的特性，等于默认不存在。**

排版代码写得再完整，被 `if` 包住且默认条件不满足，就是死代码——
而它不会报错，只是所有东西都长成一样。

这类问题检测器看不见：字号相同不违反任何几何约束。
