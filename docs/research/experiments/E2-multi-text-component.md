# 实验 E2：多文本区组件（标题 / 说明 / 状态）

**日期：** 2026-11-19
**状态：** 完成（Verified）
**依据 Goal：** §4.2 C（组件不应只被限制为一个矩形加一段文本）

---

## 一、问题

Goal §4.2 C 要求组件研究：

> 标题区域、说明区域、多文本区域、状态区域、标题条、边框和背景、多种组件样式、嵌套结构

**问题**：当前引擎能否表达「一个组件内部有信息分区」？

---

## 二、输入

单个节点，三行文本分别代表标题、技术栈、状态：

```json
{"id":"svc","text":"订单服务\nJava 17 / Spring Boot\n3 实例 · 健康",
 "bounds":{"x":5,"y":4,"w":3.2,"h":1.8}}
```

---

## 三、结果

| 项 | 实测 |
| --- | --- |
| 创建 | ✅ 成功 |
| 读回文本 | ✅ `"订单服务\nJava 17 / Spring Boot\n3 实例 · 健康"` 完整保留 |
| 样式字段 | `fill`、`fillPattern`、`font`、`hAlign`、`stroke`、`strokePattern`、`strokeWidth`、`vAlign` |
| **分区样式** | ❌ **无** |

**关键**：三行文本共用**同一套样式**。无法做到「标题 12pt 加粗、说明 9pt 常规、状态 8pt 灰色」。

---

## 四、结论

**结论（Verified）**：当前引擎的组件是「一个形状 + 一段多行文本 + 一套样式」。

Goal §4.2 C 要求的「标题区域 / 说明区域 / 状态区域」**无法表达**——它们要么全部同样式，
要么拆成多个独立对象。

### 4.1 拆成多个对象是否可行？

理论上可以：一个 `Node` 作背景框，上面叠 3 个 `TextBlock`。
但这样做的问题是：

| 问题 | 说明 |
| --- | --- |
| 丢失「属于同一组件」的语义 | `TextBlock` 没有 `GroupId`，无法绑定到 Node |
| 移动组件需同步移动 4 个对象 | 引擎不支持复合对象的原子移动 |
| 读回后无法识别它们是同一组件 | 无关联字段 |

**因此「拆成多个对象」不能替代「组件内分区」。**

---

## 五、对产品的影响

| 场景 | 当前 |
| --- | --- |
| 简单组件（只有名称） | ✅ 可做 |
| 组件含标题 + 一行说明 | ✅ 可做（用 `\n`，同一样式）|
| 组件含标题 + 说明 + 状态（**不同字号/颜色**）| ❌ 不可做 |
| 组件有标题条（顶部色带）| ❌ 不可做 |

**这直接决定 Level 2 的可行性**：Goal §4.2 C 的要求属于 E2（表达能力），当前未达到。

## 六、可能的实现方向（未实施）

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| `Node.TextRuns[]`（每行独立样式） | 模型简单，向后兼容 | 需改 Writer/Reader，且 Visio 的字符级样式的表达方式需研究 |
| `Node.Sections[]`（命名文本区，各有 bounds） | 表达力最强 | 模型复杂度高，布局需处理区内定位 |
| 复合对象（Node 含子 TextBlock） | 复用现有 TextBlock | 需新增父子关系，且 Visio 侧如何表达未知 |

**选择哪一个需要研究 Visio 的 Character Section 能力**——本机无 Visio，**Blocked**。
