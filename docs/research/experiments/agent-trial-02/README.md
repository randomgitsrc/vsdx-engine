## 三、这个结果说明了什么

### 3.1 它在验证基础行为，不是在设计图

探测夹具是**最小可能的验证**：一个容器、三个节点、一条边。
目的是确认「我写的坐标会不会被引擎改掉」。

**一个对文档有信心的 Agent 不会先做这个。**

### 3.2 它选了 model 格式，不是 IR —— 而且这可能是文档结构导致的

探测夹具用的是 `pageSize` / `groups` / `bounds`——**model 格式**，即手写坐标。

我最初记为「它读了建议，没有采纳」。**这个判断站不住。** 文档顺序是：

| 位置 | 内容 |
| --- | --- |
| §3（行 107）| **Write the model** —— 第一个出现的写法 |
| §4（行 171）| Create and render —— 用 model 的教程 |
| §5a（行 316）| The IR is a different format —— **晚 209 行** |

**Agent 读到 §3 就学会了 model 格式并动手，可能根本没走到 §5a。**

所以更准确的描述是：**文档把冷门写法放在了前面，且没有说明「这是两条路之一」。**

### 3.3 探测本身是成功的

`create` 完整保留了请求的几何：页面 `11.69×8.27`、容器 `6.00×2.20` 原样。
**引擎这一侧没有问题。**

## 五、不能从这里得出的结论

- **不能**说 `SKILL.md` 的改动无效——它没走到需要那些知识的阶段
- **不能**说 Agent 无法完成这类任务——一次失败不足以判断
- **不能**说读源码成本降低了——AT-2 没读源码，但也没完成

**能说的是：一个 Agent 在只有文档时，倾向于先验证而不是先设计。**
