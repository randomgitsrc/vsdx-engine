# 实验 E13：总线分叉点标记

**日期：** 2026-11-20
**状态：** 完成（已实施）
**依据：** 第四轮评审 P6「总线扇出必须有 junction dot」

---

## 一、问题

总线上分出多条支线时，页面上**没有任何标记**说明它们同源。读者看到的是几条恰好从相近位置开始的线。

**更糟的是反向误读**：一条线终止在另一条线附近，看起来像**接入**了它。第四轮评审把 `deploy` 的两个 API 实例读成互相连接，是同一个机制。

## 二、实现

`JunctionMarks.Apply` 在**路由之后**运行：

1. 收集所有 routed 边中的水平/垂直段
2. 按「方向 + 位置」分组，留下 ≥2 条边共享的干线
3. 在每条支线离开干线处放一个 `Ellipse` 节点（0.10 英寸，深灰 `#37474F`）

**为什么用节点而不是路径装饰**：Writer 没有在连接线上画点的能力，而小椭圆是下游都能处理的图元。

实测 `deploy-topology`：3 个 junction marks，渲染图总线上可见两个深色圆点。

## 三、一个设计冲突

**加入后 4 个场景分数掉到 0。**

```
edge.through-node (6)
  连线 'd3' (lb → api1) 穿过无关节点 'junction-page-1-0'
```

因为圆点**是节点**，而 `edge.through-node` 检测连线是否穿过无关节点——
**我添加的注释元素被当成了图形主体。**

### 修法

`LayoutAnalyzer` 排除 `junction-` 前缀的节点：

> Junction marks sit on the connectors by design: they are annotations, not shapes a line can
> "pass through".

**这是一个通用问题**：任何「附加在图上的注释」都会被几何检测器当成图的一部分。
虚线、标签、标记都需要各自的豁免规则，而每加一种就要加一条。

## 四、结果

| 场景 | 加标记前 | 加标记后 |
| --- | --- | --- |
| `cbo` | 92 | 92 |
| `deploy-topology` | 88 | 88 |
| `user-data-flow` | 100 | 100 |

分数不变，注释不干扰检测。

## 五、边界

- 只在 ≥2 条边共享干线时触发
- 落在节点内部的点会被跳过（避免看起来像形状的一部分）
- 检测器靠 `junction-` **前缀**识别，这是约定而非类型——改名会破坏豁免

最后一点是隐患：更稳的做法是给 `Node` 加一个 `Role = "annotation"` 字段。
本次未做，因为那要改动模型与 schema。
