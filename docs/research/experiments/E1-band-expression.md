# 实验 E1：通条（Band）能否用现有模型表达

**日期：** 2026-11-19
**状态：** 完成（Partially Verified）
**依据 Goal：** §4.2 D（通条）、§8.5（实验要求）

---

## 一、问题

Goal §4.2 D 把「通条」列为重点研究对象：

> 横向共享服务条、纵向贯穿多个层的安全能力、横跨多个区域的统一管理服务。
> 通条不只是普通节点，它可能具有跨层或跨区域的视觉和语义关系。

**问题**：当前引擎能否表达纵向贯穿三层的通条？它保持了几何，还是也保持了语义？

---

## 二、输入

三层架构，右侧一个 `h=7`、跨越全部三层的节点（`id=band`），文本「统一日志 / 审计 / 监控」。

```json
{"id":"band","text":"统一日志 / 审计 / 监控",
 "bounds":{"x":9,"y":4.5,"w":1.6,"h":7}}
```

| 层 | id | y 范围 |
| --- | --- | --- |
| 接入层 | `l1` | 6.5 – 8.5 |
| 服务层 | `l2` | 3.5 – 5.5 |
| 数据层 | `l3` | 0.5 – 2.5 |

---

## 三、操作

```bash
vsdx-tool create --input .exp/band.json --output .exp/band.vsdx --json
vsdx-tool export-model --input .exp/band.vsdx --output .exp/back.json
```

---

## 四、结果

| 项 | 实测 |
| --- | --- |
| 创建 | ✅ ok，4 shapes |
| 兼容性问题 | 无 |
| 通条几何 | ✅ `h=7`，y[1,8]，**确实跨越三层** |
| 通条 `groupId` | ❌ **`null`** |

---

## 五、结论

**几何表达：成功。** 通条的视觉形态可以被当前模型生成，且读回保持。

**语义表达：失败。** `groupId` 为 `null`——通条在模型里是**独立于三层之外的节点**，
不是「同时属于 l1/l2/l3 的公共能力」。

两者在渲染图上**看起来一样**，但在 Visio 中语义不同：

| 做法 | 语义 |
| --- | --- |
| 当前 | 一个不属于任何层的长矩形，恰好盖住三层范围 |
| 专业 | 一个通条，其存在意义是「同时属于 l1/l2/l3」 |

**因此**：Goal §4.2 D 要求的「跨层语义」**当前不支持**，只能得到视觉近似。

---

## 六、对产品的影响

| 场景 | 当前是否可行 |
| --- | --- |
| 上层 Agent 需要「看起来像通条」 | ✅ 可行 |
| 上层 Agent 需要「移动通条时三层联动」 | ❌ 不可行——它不属于任何层 |
| Level 2 声称支持「横向通条 / 纵向贯穿」 | ⚠️ 只能写「视觉近似」 |
